SOURCE 1 — 'Financial Sentiment Analysis Using FinBERT with Application in Predicting Stock Movement', Jiang & Zeng (arXiv:2306.02136v3, 11 Jun 2025; submitted 3 Jun 2023) — https://arxiv.org/abs/2306.02136 (ResearchGate URL 371311096 returned HTTP 403; identical paper recovered from the arXiv primary)
- Status: retrieved (primary arXiv HTML v3). RG URL UNVERIFIED — 403.
- Design: NOT a movement classifier. Target = next-day closing price (regression), loss = MSE. No accuracy/AUC/returns reported, no class-balance reported. Report author's framing: LSTM > ARIMA, FinBERT-sentiment > plain LSTM, FinBERT+LSTM best.
- Models compared: (a) ARIMA(1,1,2) on log-transformed prices (stationarity via ADF, differencing; chosen by ACF/PACF + info criteria); (b) LSTM numeric-only (same arch, no sentiment); (c) FinBERT + DNN (sentiment concat with O/H/L/V + lagged close, MinMax; DNN = input-norm, two dense 256 LeakyReLU, linear output; Adam lr 1e-3 with decay, <=1000 epochs, batch 100, early stop patience 200, 20% val); (d) base BERT ('bert-base-uncased') + LSTM replacing FinBERT (to isolate domain adaptation); (e) proposed FinBERT + LSTM. NOTE: no Loughran-McDonald/lexicon/textblob numeric baseline appears in the experiments — LM (Loughran & McDonald 2011/2016) is cited only as related 'word-counting' work in the original thesis, not benchmarked numerically here.
- Formulae (exact): softmax P(class_i)=e^{logit_i}/Σ_j e^{logit_j}, i∈{positive,negative,neutral}; per-article SentimentScore=P(positive)−P(negative) (range −1..1); daily aggregation SentimentScore_t=(1/N_t)Σ_{n=1}^{N_t}[P_n(positive)−P_n(negative)] where N_t=#articles for that ticker on day t; NSI_t=1 if return_t>s, 0 if −s<=return_t<=s, −1 if return_t<−s, with s=0.01 and return_t=(Close_t−Open_t)/Open_t; MinMax x_scaled=(x−x_min)/(x_max−x_min) (separate scalers for inputs and for target close).
- Aggregation/window: per-day, per-ticker simple MEAN of per-title (P(pos)−P(neg)) over all headlines that day. Non-trading days (weekends/US holidays): news sentiment aligned to the NEXT available trading day. LSTM input X_t concatenates S_t with lagged O,H,L,V,C over look-back k=60 days; sequence max length 512 tokens (padding+truncation); only news TITLES (not bodies) used.
- Training: LSTM 2 layers x 100 hidden units (tanh/sigmoid; first return_sequences=True, second False), Dense 25 ReLU, Dense 1 linear. Adam lr 0.001, <=100 epochs, batch size 1, early stopping patience 20 on val MSE (val = last 10% of train, chronological). Strict temporal 90/10 split (80/20 tried first, 'less satisfactory').
- Data: merged Kaggle 'Historical Financial News Archive' (>800 US companies, 12 years up to 2019) + 'Daily Financial News for 6000+ Stocks' (analyst_ratings_processed.csv); dedup by unique title; = 1,056,471 records (titles+dates+tickers); market data via yfinance. Per-stock MSFT: 7,875 raw rows -> 1,440 after processing.
- Validation numbers (Table 1): ARIMA val loss 0.00975 (also MSE 0.00975, MAE 0.07154, RMSE 0.09876); LSTM train 1.0206e-3 / val 1.1937e-3; BERT+LSTM train 1.0216e-4 / val 3.3132e-4; FinBERT+DNN train 1.4674e-4 / val 3.4177e-4; FinBERT+LSTM (proposed) train 9.1701e-5 / val 3.1975e-4.
- Stated limitations: per-stock sample tiny after processing -> overfitting (loss dropped within ~3 epochs); sentiment from titles only; margin of FinBERT over base BERT is modest (off-the-shelf model not task-tuned); model underpredicts close price in the long run; data ends 2019.
- Engine-relevant: implementable directly with OHLCV — daily per-ticker mean of per-headline (P(pos)−P(neg)); NSI needs only OHLC (s=0.01). Paper uses NO options/IV, NO analyst targets, NO prediction-market probs, NO FRED, NO per-article relevance score, NO real-time streaming window — only a single 60-day sequence per stock and a one-shot 90/10 split (no walk-forward). The engine's per-article relevance 0–100 is absent from this paper; to use it one must map it into the sentiment score.

SOURCE 2 — QuantConnect LEAN docs, 'FinBERT' (Writing Algorithms > Machine Learning > Hugging Face > Popular Models) — https://www.quantconnect.com/docs/v2/writing-algorithms/machine-learning/hugging-face/popular-models/finbert
- Status: retrieved (full page incl. both code examples).
- Implementation contract: load `ProsusAI/finbert` via `TFBertForSequenceClassification.from_pretrained(model_path, local_files_only=True)` + `BertTokenizer`; `set_seed(1, True)` for reproducibility; softmax `tf.nn.softmax(outputs.logits, axis=-1)` -> per-article [neg, neutral, positive]; documented example output `array([[0.21346861, 0.46771246, 0.318819]])` (more positive than negative but likely neutral).
- Exact per-ticker aggregation (rolling window): Example 1 titled '10-day Sentiment Score' — 'gets the Tiingo News articles that were released for the asset over the previous 10 days and then feeds them into the pre-trained FinBERT model. It then aggregates the sentiment scores of all the news releases.' Window = `self.history[TiingoNews](security.dataset_symbol, 10, Resolution.DAILY)`. Aggregation function `_aggregate_sentiment_scores`: n=scores.shape[0]; weights = np.exp(np.linspace(0,1,n)); weights /= weights.sum(); weighted_scores = scores*weights[:,None]; aggregated_scores = weighted_scores.sum(axis=0). i.e. EXPONENTIALLY INCREASING recency weights w_i = e^{linspace(0,1,n)} normalised to sum 1, applied to the [neg,neutral,pos] probability vectors, then column-summed.
- How sentiment feeds the model: decision rule `weight = 1 if scores[2] > scores[0] else -0.25` (long when aggregated P(pos) > aggregated P(neg), else short 0.25); `set_holdings(..., liquidate_existing_holdings=True)`.
- Schedule: rebalance at month start on day 1 — `on(self.date_rules.month_start('SPY', 1), self.time_rules.midnight, self._trade)` — with guard `if self.is_warming_up or self.time - self._last_rebalance_time < timedelta(14): return` (min 14-day spacing). Universe reselected monthly as the most volatile of the 10 highest-dollar-volume names (std of daily pct_change over 365 days).
- Warm-up: Example 1 `self.set_warm_up(30, Resolution.DAILY)`; Example 2 `self.set_warm_up(timedelta(30))`; trading is skipped during warm-up (`is_warming_up`). Fine-tune demo (Example 2, '30-day Sentiment Score With Fine Tuning'): pulls 30 days of Tiingo news to build samples; label = market return from current news release to next release; last 100 samples, require >=10; label classes via 75/75 percentile rule (top 75% of positive-return samples -> class 2, most-negative 75% -> class 0, middle -> class 1 neutral); fine-tune TFBertForSequenceClassification(num_labels=3, from_pt=True) with Adam(lr=3e-5), SparseCategoricalCrossentropy(from_logits=True), epochs=2.
- Look-ahead caveat: the page states NO explicit 'look-ahead bias' wording; the only stated protections are warm-up (30 days), the 14-day inter-rebalance gap, chronological sample labeling (reaction measured between a release and the NEXT release), and the note 'These algorithms require a GPU node.' (exact quote). Documented use cases: long-short on most positive/negative news, liquidate on extremely negative regulatory-alert sentiment, or synthesising sentences from other datasets.
- Engine-relevant: the rolling-10-day recency-weighted aggregation is fully implementable from the engine's headline stream with timestamps + per-article [neg,neutral,pos] probabilities; the engine must supply publication timestamps and per-ticker tagging (QuantConnect uses Tiingo News). Decision uses aggregated P(pos) vs P(neg) only; the 3-vector is retained. Monthly cadence with 14-day min gap and 30-day warm-up are the documented scheduling constraints. Requires a GPU node for the model.

Positive, Negative, or Neutral ... with softmax probability outputs ... along with an overall sentiment score'; FAQ says 'FinBERT classifies text into three sentiment categories: Positive, Negative, and Neutral. It provides softmax probability outputs for all three classes along with an overall sentiment score.' (The 'overall sentiment score' mapping is not disclosed.)
- Model card (primary, https://huggingface.co/ProsusAI/finbert): exact model name/id `ProsusAI/finbert`; task text-classification; architecture `BertForSequenceClassification` (BERT-base); framework files pytorch_model.bin, tf_model.h5, flax_model.msgpack; label set = 3 softmax classes {positive, negative, neutral}; fine-tuned on Financial PhraseBank (Malo et al. 2014); repo sha 4556d13015211d73dccd3fdd39d39232506f3e43, last modified 2023-05-23; 5.34M downloads / 1.24K likes. The HF model card itself states NO corpus size, date range, max tokens, or licence field (cardData has only language/tags/widget) — UNVERIFIED on-card: licence; the upstream GitHub README is reported as Apache-2.0 (https://github.com/ProsusAI/finBERT) — secondary-source claim, treat as INFERENCE.
- Primary corpus/benchmark facts (Araci 2019, 'FinBERT: Financial Sentiment Analysis with Pre-trained Language Models', arXiv:1908.10063): further pre-training corpus = TRC2-financial, a keyword-filtered subset of Reuters TRC2 (TRC2 = 1.8M news articles published by Reuters 2008–2010); TRC2-financial = 46,143 documents, more than 29M words, nearly 400K sentences. Fine-tune dataset = Financial PhraseBank = 4,845 English sentences randomly selected from LexisNexis financial news, annotated by 16 finance/business people for effect on the mentioned company's stock price; label distribution All: positive 28.1% / negative 12.4% / neutral 59.4% (100%-agreement subset: 25.2/13.4/61.4, n=2262). Input length: thesis implementation uses maximum sequence length 64 tokens (padding/truncation; BERT itself supports 512, and the applied paper used 512).
- Published benchmarks (Araci 2019): Financial PhraseBank, all data — FinBERT Loss 0.37 / Acc 0.86 / F1 0.84; baselines LSTM 0.81/0.71/0.64, LSTM+ELMo 0.72/0.75/0.70, ULMFit 0.41/0.83/0.79, LPS 0.71/0.71, HSC 0.71/0.76. 100%-agreement subset — FinBERT 0.13/0.97/0.95; LSTM 0.57/0.81/0.74; LSTM+ELMo 0.50/0.84/0.77; ULMFit 0.20/0.93/0.91; FinSSLX 0.91/0.88. Further-pre-training ablation: Vanilla BERT 0.38/0.85/0.84, FinBERT-task 0.39/0.86/0.85, FinBERT-domain 0.37/0.86/0.84. FiQA regression — FinBERT MSE 0.07 / R² 0.55 vs Yang 0.08/0.40, Piao & Breslin 0.09/0.41.
- Engine-relevant: FinBERT probability output is a 3-way softmax; finbert.org's host does not expose the calibration/mapping. A per-article LLM relevance score (0–100) is a RELEVANCE not a SENTIMENT measure and is not in any of the three sources; to approximate FinBERT's P(pos)/P(neg) the engine must build a labelled calibration set (headlines scored by FinBERT), then fit a mapping (e.g. isotonic/Platt or a small classifier) from relevance + features -> class probabilities; rank correlation with labels can be assessed on that set but is NOT guaranteed by construction. A daily/weekly rolling aggregation additionally requires from the engine's news pipeline: per-article publication timestamps, per-ticker association, article counts N_t per day, and a policy for non-trading-day alignment (Source 1: shift to next trading day; Source 2: 10-day trailing bar window with recency weights). Required inputs none of the three sources use: options/IV chain, analyst ratings/price targets, prediction-market probabilities, FRED macro series.
